# Writing workflow

Current user instructions take precedence. Topic selection and script drafting are separate runs unless the user has already supplied script-ready core content or explicitly asks to fuse selected source files.

## A. Topic shortlist

1. Read the selection rules in actionable-rules.md §§3, 5.1–5.4. Do not read the material catalog.
2. Rebuild the Instagram and Xiaohongshu performance pools with the two selection scripts. Apply all platform-specific author, culture/depth, completeness, usability, and risk exclusions.
3. Match the same concrete problems across platforms and rank eligible topics with the stable Tier 1, Tier 2, and experimental tie-break rules. Select the first three distinct topics; text sources do not affect ranking.
4. For each selected topic, search the complete Instagram, Xiaohongshu, and text directories for every materially related eligible source. Read enough of each match to reject superficial keyword matches and apply exclusions.
5. Return, for each topic: topic name, tier, data/performance basis, completeness/filmability reason, and all related eligible source files grouped by platform. Use exact basenames and clickable absolute local paths. Then stop for the user's source and core-content selection.

## B. Core content, explicit source fusion, or existing drafts to scripts

1. Classify each submitted unit as user-core drafting, explicit source fusion, or draft maintenance. User-core drafting needs script-ready core content and exact source names. Explicit source fusion needs two or more exact selected source names plus a clear request to fuse, merge, or comprehensively rewrite them; the selected files themselves are the submitted content. Draft maintenance uses the selected drafts plus the user's requested changes. Each unit produces at least one script. Do not infer another topic or combine units unless the user explicitly requests the combination. Split one unit into multiple related scripts only when complete conversational wording, necessary transitions, and all required information cannot fit within 340 English words; each part must have its own coherent promise and source list.
2. For user-core drafting, resolve named sources only as needed to verify existence, exact local links, and non-action textual support; the submitted core or selected draft, not the full source, is the inventory. For explicit source fusion, read every selected source completely and build a separate inventory for each source, recording every substantive claim, action, point, example, cultural observation, location, direction, count, duration, quantity, mechanism, conclusion, and qualifier. Consolidate only exact semantic repetition. Do not discard a point because another source covers the same broad idea, because it seems secondary, or because one script would become too long. Promotional packaging and source CTAs may be removed. Do not add content from unselected sources or general knowledge.
3. If the core contradicts accessible non-action source text or names an unavailable or excluded source, report the exact blocker for that unit. In explicit source fusion, also report mutually incompatible source claims or any point that internal risk screening prevents from appearing; stop before finalization rather than silently omitting it. Preserve user-supplied action details without resolving them from source media, and do not fill gaps from general knowledge or another source.
4. Draft each valid unit in the main agent. Do not use drafting or review subagents unless the user explicitly asks for subagents in the current request; earlier permission does not carry forward. When explicitly requested, each subagent receives only its assigned core, named sources, persona, editorial rules, and output requirements, and must not search for or merge additional content. The main agent still owns final review, revision, file writing, validation, and catalog updates.
5. The main agent checks every returned draft against the unit-level inventory in both directions. Every substantive script statement must be supported by the applicable boundary. In ordinary tasks, every relevant core item must be represented unless internal risk screening excludes the whole item, it is promotional or exactly duplicative, or the user excluded it. In explicit source fusion, repeat this reverse check separately for every selected source and require a visible landing place for every substantive point; presumed irrelevance, pacing, and length are not omission reasons. Any allowed omission needs a specific working-note reason.
6. Apply the cover, caption, hook, identity, structure, American spoken-English, CTA, and no-safety-copy rule. The caption must distill the central idea in one or two concise English sentences, avoid retelling the script, and end with 5–10 relevant English hashtags. Humanize with the installed `humanizer-zh` skill plus account-persona.md, without altering grounded information. Add or synchronize the faithful Chinese translation only after the English is stable.
7. In the main agent, review the caption and first sentence separately, then review the full bilingual draft for grounding, promise fulfillment, spoken language, translation fidelity, CTA, and the complete absence of safety-processing copy. For explicit source fusion, include a per-source completeness pass before approving the full script. After every local edit to a completed draft, restart the entire final-review chain for every affected file: rebuild and check the unit inventory in both directions; review the cover and caption; isolate and review the first sentence; review the full spoken script; reapply humanization; synchronize and compare the Chinese translation; check the CTA and no-safety-copy rule; rerun batch validation; then update or reconcile the catalog. Never limit review to the edited sentence or the mechanically affected check. Use a separate reviewer only when the user explicitly requests subagents in the current request; report whether review was main-agent or independent.
8. Write files using output-contract.md and validate the whole N-file delivery in one command. Mechanical validation does not replace grounding, hook, language, translation, CTA, or the semantic check for safety-processing copy.
9. After finalization, update the catalog with only the new files:

   `node scripts/update-material-catalog.mjs --draft <file-1> [--draft <file-2> ...]`

   This must mark every cataloged named source used by those drafts as used, set its production date, and link the latest draft while preserving the user's publication time. If the task deleted or renamed existing output files, instead run `node scripts/update-material-catalog.mjs --reconcile-current` to rebuild generated usage state from the drafts that still exist while preserving publication times and custom manual statuses. Do not use the catalog to select topics or write scripts.

Deliver the N file links and concise review status. Keep inventories and review notes transient; do not add them to the script files or persistent skill instructions.
